# Cloudflare 网盘 · 网页版部署文档（006 性能优化版）

一套基于 **Cloudflare Workers + R2 + D1 + Turnstile** 的自建网盘系统。
本文档面向 **网页控制台（dash.cloudflare.com）** 手动部署，全程点击操作，
**无需安装 Wrangler CLI**、无需本地命令行环境。

| 源文件 | 大小 | 说明 |
|---|---|---|
| `006_主_性能优化版.js` | 175 KB / 2667 行 | 前端页面 + 管理后台 + D1 日志 + 多桶聚合 + 同源静态资源 |
| `006_副_性能优化版.js` | 16.7 KB / 355 行 | 纯 R2 代理 API（分块上传、搜索索引缓存） |
| `vue.global.prod.js` | 170 KB | 配套素材，需上传到 R2 |
| `bg.webp` | 39 KB | 配套素材（可选），需上传到 R2 |

> 💡 006 相对 005 是**安全加固 + 性能优化**版本，业务功能完全一致（复制链接、单页预览、容量统计、操作日志都在）。
> 主要变化：去掉默认密码、引入会话令牌、错误脱敏、上传路径校验、Tailwind 改为预编译内联、Vue 与背景图改为同源自托管。
> 详见文末「附录 A：006 相对 005 的变更」。

## 00 · 快速参考速查

> 部署过程中最常用的绑定与变量，可随时回到本节对照

### 需要创建的云资源

| 资源 | 数量 | 用途 | 说明 |
|---|---|---|---|
| **R2 存储桶** | 至少 1 个 | 存储网盘文件 + 静态资源 | 可创建多个桶实现容量扩展 |
| **D1 数据库** | 1 个（可选） | 操作日志 | 不配置则日志功能不可用，主功能不受影响 |
| **Turnstile** | 1 个站点（可选） | 登录人机验证 | 强烈建议开启，防暴力破解管理密码 |
| **Worker** | 2 个 | 主 Worker（网盘）+ 副 Worker（R2 代理） | 副 Worker 仅多账号扩容时需要 |

### 绑定（Bindings）速查

| 绑定到 | 类型 | 变量名（不可更改） | 选择资源 | 必须 |
|---|---|---|---|---|
| 主 Worker | R2 Bucket | `MY_BUCKET` | 主桶（第 3 节创建） | **必填** |
| 主 Worker | D1 Database | `D1_DB` | 日志库（第 4 节创建） | 可选 |
| 主 Worker | R2 Bucket | `MY_BUCKET2`、`MY_BUCKET3`… | 附加本地桶 | 可选 |
| 副 Worker | R2 Bucket | `MY_BUCKET` | 副桶（第 3 节创建） | **必填** |

### 环境变量（Environment Variables）速查

| 所在 Worker | 变量名 | 作用 | 默认 / 示例 |
|---|---|---|---|
| 主 Worker | `PASSWORD` | 管理员登录密码 | **无默认值，必须设置**（未设置则管理功能整体关闭） |
| 主 Worker | `ADMIN` | 管理后台路径 | `admin`（访问 `/admin`） |
| 主 Worker | `BUCKETS` | 聚合桶配置（JSON 字符串） | 见第 7.3 节示例 |
| 主 Worker | `PUBLIC_READ` | 是否允许未登录浏览 / 下载 | `true`（设为 `false` 则必须登录） |
| 主 Worker | `BG_URL` | 登录页背景图地址（静态资源缺失时的兜底） | 内置默认壁纸 URL |
| 主 Worker | `TURNSTILE_SITE_KEY` | Turnstile Site Key | 可选 |
| 主 Worker | `TURNSTILE_SECRET_KEY` | Turnstile Secret Key（建议加密） | 可选 |
| 副 Worker | `AUTH_TOKEN` | 主副 Worker 间鉴权令牌（建议加密） | **无默认值，必须设置**（未设置则副 Worker 拒绝一切写操作） |

> ⚠️ **两个 Worker 的代码里 CORS 来源写死了 `https://pan2.ppig.eu.cc`**。
> 如果你使用自己的域名，部署前请先按第 9 节 修改两个文件，否则跨域请求会被浏览器拦截。

## 01 · 项目架构

> 一个前端 Worker + 一个纯 API Worker，通过 R2 / D1 / Turnstile 组合工作

**浏览器（用户）**

  直接访问主 Worker 渲染出的网盘前端页面与管理后台，无需单独托管前端。

  ↓ HTTPS

**主 Worker（`006_主_性能优化版.js`）**
  - 渲染前端页面（`/` 与 `/admin`）
  - 管理员登录（密码 + Turnstile）→ 签发 12 小时会话令牌
  - 列表 / 搜索 / 上传 / 分块上传
  - 新建目录 / 删除 / 移动
  - 下载防盗链令牌（HMAC · 10 分钟）+ 同 IP 限速
  - **同源静态资源**：`/_static/vue.global.prod.js`、`/_static/bg.webp`
  - 背景图代理 `/api/bg-image`（静态资源缺失时的兜底）
  - D1 操作日志（`/api/logs`）
  - 多桶容量聚合（每桶 10GB 上限显示）

  ↓ 本地 R2 绑定直连 / 服务端代理转发（endpoint + token）

**本地 R2 桶**
  - 绑定名 `MY_BUCKET` 及其扩展桶
  - 主 Worker 直接读写
  - 同时存放静态资源（`.static/vue.global.prod.js`、`.static/bg.webp`）

**副 Worker（`006_副_性能优化版.js`）**
  - 纯 API：`/api/list`、`/api/raw/`、`/api/upload`
  - 分块上传：initiate / upload-part / complete / abort
  - 新建目录 / 删除 / 移动 / 容量统计
  - 以 `X-Auth-Token` 鉴权（未配置 `AUTH_TOKEN` 时**一律拒绝**，不会静默开放）
  - 自带 R2 绑定 `MY_BUCKET`

  ↓ 副 Worker 自有 R2 绑定

**远程 R2 桶（第二账号扩容）**

  副 Worker 放在另一个 Cloudflare 账号，即可把第二个账号的 R2 免费额度聚合进同一个网盘。

**各组件职责**

- **主 Worker**：一个文件内同时包含后端 API 与前端 HTML，负责页面渲染、登录鉴权、所有文件操作，并决定数据落在本地桶还是远程副桶。
- **副 Worker**：纯后端 R2 代理，不渲染页面。主 Worker 以「完整 URL + AUTH_TOKEN」方式服务端调用它，主要用途是跨账号 / 跨桶扩容。
- **D1 数据库**：记录「下载 / 预览 / 上传 / 删除 / 新建目录 / 移动」等操作日志，供管理后台查询；未绑定 D1 时代码自动跳过，不影响主功能。
- **R2 搜索索引缓存**：桶内自动维护 `.r2index.json`（TTL 60 秒），减少频繁全量扫描带来的 Class A 操作费用。

## 02 · 部署前准备

> 开始前请确认以下事项，建议全部准备完毕再动手

| 事项 | 说明 |
|---|---|
| **Cloudflare 账号** | 注册地址：https://dash.cloudflare.com；副 Worker 用于跨账号扩容时需另一个账号（同账号也可以） |
| **域名**（可选但推荐） | 两个文件的 CORS 写死了 `https://pan2.ppig.eu.cc`；使用自己的域名需按第 9 节 修改后再部署 |
| **需要的云资源** | R2 存储桶（至少 1 个）、D1 数据库（1 个）、Turnstile 站点（可选，推荐） |
| **源文件** | `006_主_性能优化版.js`、`006_副_性能优化版.js` |
| **配套素材** | `vue.global.prod.js`、`bg.webp`（第 8 节要上传到 R2） |
| **管理员密码** | 006 版本**没有默认密码**，请先想好一个强密码 |

> 这样主 Worker 配置 `BUCKETS` 时可以直接填入副 Worker 的线上地址。

## 03 · 创建 R2 存储桶

> Cloudflare 对象存储，本项目用它存放网盘文件

R2 免费额度约为 **10GB 存储 / 每月 100 万次 Class A 操作 / 1000 万次 Class B 操作**（以官网最新定价页为准）。
本项目内置的容量统计以每桶 10GB 为上限显示。

### 3.1 创建主桶

1. **进入 R2 页面** — 打开 https://dash.cloudflare.com → 左侧菜单 **R2** → **Create bucket**。
2. **填写桶信息** — 输入桶名（例如 `pan-storage`），地区选择默认「自动」即可 → 点击 **Create bucket**。
3. **记录桶名** — 记下这个桶名，后面绑定 Worker 时需要选择它（主 Worker 的 `MY_BUCKET` 绑定指向它）。

### 3.2 创建副桶（可选）

- 要用「副 Worker + 第二个账号的 R2」扩展容量时，用**另一个 Cloudflare 账号**（或同账号）再建一个桶，例如 `pan-storage-2`。
- 只用主 Worker 单桶的话，跳过此步即可。

> ✅ 一个账号可以创建多个 R2 桶（主 Worker 支持挂多个本地桶，通过 `MY_BUCKET2`、`MY_BUCKET3`… 绑定并在 `BUCKETS` 中声明）。

## 04 · 创建 D1 数据库

> Cloudflare 的无服务器 SQLite，用于记录网盘操作日志

1. **进入 D1 页面** — 左侧菜单 **Workers & Pages** → 顶部标签 **D1** → **Create database**。
2. **命名并创建** — 输入数据库名（例如 `pan-logs`）→ 点击 **Create**。
3. **记录数据库名** — 后面绑定到主 Worker，变量名固定为 `D1_DB`。

> ⚠️ D1 不是必须的：未绑定时代码会**静默跳过日志记录**，网盘主功能不受影响，
> 但管理后台的「操作日志」面板不可用。表结构在部署后用第 10 节 的按钮初始化。

---

## 05 · 创建 Turnstile 人机验证（可选，推荐）

> Cloudflare 免费的无感验证码，防止管理密码被暴力破解

1. **添加站点** — 打开 https://dash.cloudflare.com → 左侧 **Turnstile** → **Add site**。
2. **填写站点信息** — 站点域名填你的主域名（如 `ppig.eu.cc` 或 `pan2.ppig.eu.cc`），Widget 模式选 **Managed** 或 **Non-interactive**。
3. **记录 Site Key 与 Secret Key** — 创建后会得到两个值：**Site Key**（挂到前端页面）、**Secret Key**（后端验证用），稍后填入主 Worker 环境变量 `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY`。

> ⛔ **006 版本的 Turnstile 是「配了 Secret Key 就启用」**。
> 因此 **Site Key 与 Secret Key 必须成对配置**：只填 Secret 不填 Site，前端渲染不出验证码部件，会导致**谁也登录不上**。
> 两个都不填则跳过人机验证，只校验密码。

## 06 · 部署副 Worker

> `006_副_性能优化版.js`：纯后端 R2 代理 API，供主 Worker 跨账号聚合调用

### 6.1 创建 Worker 并粘贴代码

1. **创建 Worker** — 左侧菜单 **Workers & Pages** → **Create application** → **Create Worker**。
2. **命名并部署** — 输入名称，例如 `pan-api`（名称决定默认域名 `pan-api.<你的子域>.workers.dev`）→ 点击 **Deploy**。
3. **粘贴代码** — 创建完成后点击 **Edit code**，把 `006_副_性能优化版.js` 的**全部内容**粘贴进编辑器（替换默认模板）→ 点击右上角 **Deploy**。

### 6.2 绑定 R2 桶

1. Worker 页面 → **Settings** → **Variables and Secrets**。
2. 在 **Bindings** 区域 → **R2 bucket bindings** → **Add binding**。
3. **Variable name** 填：`MY_BUCKET`（代码中固定使用，不要改）。
4. **Bucket** 选择3.2节创建的副桶（如 `pan-storage-2`）→ **Save**。

### 6.3 设置认证令牌（必填）

1. 仍在 **Variables and Secrets** 页面 → **Environment Variables** → **Add**。
2. **Variable name**：`AUTH_TOKEN`。
3. **Value**：生成一段长随机字符串（本地执行 `openssl rand -hex 32`，或用在线随机生成器），**保存好**，主 Worker 配置 `BUCKETS` 时要用。
4. 建议点开 **Encrypt** 加密存储（保存前选择加密选项）。

> ⛔ **006 版本的行为变了**：005 版本里 `AUTH_TOKEN` 未配置时副 Worker **完全开放**（任何人可增删改）；
> 006 改成未配置时 **一律拒绝**。所以这一项现在是**必填**，漏配的表现是主 Worker 侧所有远程桶操作 401。

### 6.4 自定义域名（可选）

- 副 Worker 被主 Worker 用 `https://…workers.dev` 地址**服务端调用**，不需要自定义域名即可工作。
- 若想给它独立域名：Worker → **Settings** → **Domains & Routes** → **Add** → 选 **Custom Domain** 或 **Route**。

> ⛔ **CORS 提醒**：`006_副_性能优化版.js` 第 64 行、第 73 行写死了 `Access-Control-Allow-Origin: https://pan2.ppig.eu.cc`。
> 如果你把副 Worker 的 API 直接暴露给浏览器使用（而非仅主 Worker 服务端代理），请按第 9 节 改成你的主前端域名。

## 07 · 部署主 Worker

> `006_主_性能优化版.js`：前端页面 + 管理后台 + 所有业务逻辑

### 7.1 创建 Worker 并粘贴代码

1. **Workers & Pages** → **Create application** → **Create Worker**。
2. 输入名称，例如 `pan-web` → 点击 **Deploy**。
3. **Edit code** → 把 `006_主_性能优化版.js` 的**全部内容**粘贴进去（替换默认模板）→ 点击 **Deploy**。
4. 此时可以先通过 `https://pan-web.<你的子域>.workers.dev` 访问测试（见第 11 节），再继续配置。

### 7.2 绑定资源

路径：Settings → Variables and Secrets → Bindings，每个绑定单独添加一行：

| 类型 | 变量名 | 选择 | 必填 |
|---|---|---|---|
| R2 Bucket | `MY_BUCKET` | 3.1节创建的主桶 | **必填** |
| D1 Database | `D1_DB` | 第4节创建的数据库 | 可选 |

> 💡 若要在**同一账号**下挂更多本地 R2 桶，再添加 `MY_BUCKET2`、`MY_BUCKET3` 等绑定，
> 并在 `BUCKETS` 环境变量里按下面的格式声明。

### 7.3 设置环境变量

| 变量名 | 说明 | 默认值 / 示例 |
|---|---|---|
| `PASSWORD` | 管理员密码 | **无默认值，必须设置**；未设置时 `/api/verify` 返回 503、所有管理接口 401 |
| `ADMIN` | 管理后台路径 | `admin` → 访问 `/admin` |
| `BUCKETS` | 聚合桶配置（JSON 字符串） | 见下方示例 |
| `PUBLIC_READ` | 未登录能否浏览 / 下载 | 默认 `true`（分享门户）；设为 `false` 则列表 / 下载都必须登录 |
| `BG_URL` | 登录页背景图地址 | 已内置默认壁纸 URL，可换成任意图片地址（仅当 R2 里没有 `bg.webp` 时生效） |
| `TURNSTILE_SITE_KEY` | Turnstile Site Key（必须与 Secret 成对配置） | 可选 |
| `TURNSTILE_SECRET_KEY` | Turnstile Secret Key | 可选，建议加密存储 |

#### ① 只用主 Worker 自己的桶（单桶最小配置）

```text
# BUCKETS
[{"binding":"MY_BUCKET","name":"主存储"}]
```

#### ② 主桶 + 副 Worker 远程桶（两账号扩容）

```text
# BUCKETS
[{"binding":"MY_BUCKET","name":"主存储"},{"endpoint":"https://pan-api.<你的子域>.workers.dev","token":"<副worker的AUTH_TOKEN>","name":"副存储"}]
```

说明：`endpoint` 是副 Worker 的完整线上地址，`token` 必须与6.3节设置的 `AUTH_TOKEN` **完全一致**。

#### ③ 多个本地 R2 桶

```text
# BUCKETS
[{"binding":"MY_BUCKET","name":"主存储"},{"binding":"MY_BUCKET2","name":"备份存储"}]
```

> ✅ 若**完全不设置** `BUCKETS`，代码默认按 `[{"binding":"MY_BUCKET","name":"主存储"}]` 工作，即只需要 `MY_BUCKET` 这一个 R2 绑定。

### 7.4 绑定自定义域名（关键步骤）

主 Worker 的前端页面由它自己渲染，**建议**把它挂到你的主域名上（如 `pan2.ppig.eu.cc`）：

1. Worker 页面 → **Settings** → **Domains & Routes** → **Add**。
2. 选 **Custom Domain** → 输入 `pan2.ppig.eu.cc` → 按提示在 DNS 处确认（域名已托管在 Cloudflare 时一键完成，自动添加 CNAME）。
3. 等待证书生效（通常几秒到几分钟）。

> ⛔ **CORS 提醒**：`006_主_性能优化版.js` 第 233 行、第 242 行的 `Access-Control-Allow-Origin` 写死了 `https://pan2.ppig.eu.cc`。
> 若你的主域名不是它，请按第 9 节 修改后再部署，否则管理后台接口会因跨域被浏览器拦截。

## 08 · 上传静态资源到 R2（006 新增步骤）

> 006 把 Vue 运行时和背景图改成同源自托管，这一节漏做不会白屏，但会退化成「跨境拉 CDN」的慢速版本

主 Worker 新增了两个同源静态路由，优先从 **主桶** 读取：

| 路由 | 读取顺序 | 命中时响应头 | 未命中 |
|---|---|---|---|
| `/_static/vue.global.prod.js` | `.static/` → `static/` → 桶根 | `Cache-Control: public, max-age=31536000, immutable` | 回源 unpkg 拉 `vue@3` prod 版并写入边缘缓存；两者都失败返回 502 |
| `/_static/bg.webp` | `.static/` → `static/` → 桶根 | `Cache-Control: public, max-age=31536000, immutable` | 302 跳转到 `/api/bg-image`（原来的代理兜底） |

### 8.1 上传步骤

1. 打开主桶（3.1节创建的那个）→ **Create folder**，文件夹名填 `.static`。
   > `.` 开头的目录会被网盘列表过滤，不会出现在访客可见的文件列表里。
2. 进入 `.static` 目录 → **Upload**，上传 `vue.global.prod.js`。
3. 同样位置上传 `bg.webp`（可选，不传则自动回退到 `BG_URL` 代理）。
4. 确认两个对象的 key 分别是 `.static/vue.global.prod.js` 与 `.static/bg.webp`。

> 💡 如果 R2 控制台不方便创建 `.` 开头的目录，直接上传到桶根目录也能被找到，
> 只是这两个文件会显示在网盘列表里。顺序是 `.static/` 优先，所以两边都传也不会冲突。

### 8.2 为什么值得做

| | 005 版本 | 006 版本 |
|---|---|---|
| Vue 运行时 | `unpkg.com` 上的 **dev 版**（约 600 KB，含调试代码） | 同源 **prod 版**（170 KB），`immutable` 长缓存 |
| 样式 | `@tailwindcss/browser@4` CDN，**在浏览器里实时编译 CSS**（约 282 KB 脚本 + 编译耗时） | Tailwind v4 **预编译后内联**（34 KB CSS），零运行时编译 |
| 背景图 | `/api/bg-image` 每次回源代理（105 KB） | 同源 `bg.webp`（39 KB），`immutable` 长缓存 |
| 外部依赖 | 2 个境外 CDN（jsdelivr / unpkg） | 0 个 |

首屏需要下载的资源量大约从 **1.0 MB 降到 0.3 MB**，且不再有跨境 DNS + TLS 握手。

## 09 · 修改 CORS 来源

> 仅当你的域名不是 pan2.ppig.eu.cc 时需要执行

|---|---|---|---|

> 深度防御：即使将来 token 意外丢失，也不会静默变成公开读写。

### 鉴权头的演进

| 头 | 版本 | 说明 |
|---|---|---|
| `X-Admin-Password` | 005 / 006 兼容 | 每次请求都带上明文密码，长期驻留 localStorage，风险高 |
| `X-Admin-Token` | 006 新增（推荐） | `exp:HMAC(PASSWORD, "sess:"+exp)` 形式的会话令牌，**12 小时**有效，服务端等时比较 |

前端 006 登录成功后只把会话令牌存进 `localStorage['r2_admin_sess']`，
并在页面启动时**主动清掉**旧版本留下的 `r2_admin_pwd` 明文密码。

### 分块上传接口参数（主 Worker）

| 步骤 | 请求方式 | 携带参数 |
|---|---|---|
| 1. 初始化 | `POST /api/multipart/initiate` | JSON：`{key, bucket}` |
| 2. 上传分块 | `PUT /api/multipart/upload-part` | 请求头：`X-Upload-Id`、`X-Part-Number`、`X-Target-Bucket`；URL 参数：`key`；body：分块数据 |
| 3. 完成 | `POST /api/multipart/complete` | JSON：`{key, uploadId, parts, bucket}`（`parts` 为分块 etag 列表） |
| 4. 取消 | `POST /api/multipart/abort` | JSON：`{key, uploadId, bucket}` |

远程桶场景下，主 Worker 会自动追加 `X-Auth-Token`（副 Worker 令牌）转发给副 Worker；
所有写操作统一携带 `X-Admin-Token` 请求头。

## 13 · 常见问题排查

> 部署中遇到问题先查这张表

| 现象 | 原因 / 解决 |
|---|---|
| 页面打开但接口全部失败（控制台红色 CORS 报错） | 主 / 副 Worker 的 `Access-Control-Allow-Origin` 与访问域名不一致，按第 9 节 修改 |
| `Unauthorized`（401） | 请求头缺 `X-Admin-Token` / `X-Admin-Password`，或密码错误；确认 `PASSWORD` 环境变量已设置 |
| 登录接口返回 **503** | 主 Worker **没有配置 `PASSWORD`**。006 不再有默认密码，管理功能整体关闭，去补上变量再部署 |
| 登录一直失败，且看不到验证码 | 只配了 `TURNSTILE_SECRET_KEY` 没配 `TURNSTILE_SITE_KEY`。006 里只填 Secret 就会启用校验，前端却没有部件渲染 → 两个都填或都不填 |
| 用了一会儿突然所有操作 401 | 会话令牌 12 小时过期，重新登录即可 |
| 上传报「文件名或路径非法」（400） | 006 新增的 `isSafeKey` 校验：文件名含 `..`、反斜杠、控制字符或超过 512 字符会被拒绝。改掉这些字符再传 |
| 下载提示「无效或过期的下载令牌」 | 下载链接 10 分钟过期；从页面点击下载会自动获取新令牌 |
| 提示「请求过于频繁」（429） | 同 IP 每分钟最多申请 20 次下载令牌，稍等一分钟再试 |
| 页面样式全丢 / 只有纯文字 | Vue 运行时没加载成功。检查 `/_static/vue.global.prod.js` 是否 200；若显示 `/* vue runtime unavailable */` 说明 R2 没有且 unpkg 也拉不到 |
| 背景图不显示 | `/_static/bg.webp` 未上传时会 302 到 `/api/bg-image`，这是正常兜底；要更快就按第 8 节 上传 |
| 列表里没有文件 | 检查 `MY_BUCKET` R2 绑定是否已添加；`BUCKETS` JSON 格式是否正确（可用 JSON 校验工具检查） |
| 副桶无法显示 / 上传失败 | 确认 `endpoint` 是副 Worker 完整 URL、`token` 与副 Worker `AUTH_TOKEN` 一致；副 Worker 是否已部署最新代码 |
| 「操作日志」报未配置 | D1 未绑定（`D1_DB`）或未初始化（点击第 10 节 的初始化按钮） |
| 大文件上传失败 | 分块上传走 `/api/multipart/*`；确认请求头 `X-Upload-Id`、`X-Part-Number`、`X-Target-Bucket` 与 URL 参数 `key` 齐全；Worker 已绑定目标桶 |
| 管理页面一直显示验证失败 | Turnstile 的 Site / Secret Key 不匹配，或域名未加入 Turnstile 站点白名单 |
| 修改代码后不生效 | 每次编辑后必须点 **Deploy** 重新部署；注意浏览器缓存（Ctrl+F5） |

### 其他说明

- Worker 免费计划有 CPU 时长与每日请求限制；大流量场景请在 Workers 计划页面升级付费计划。
- R2 与 D1 均按用量计费，价格以官网定价页为准。
- `.r2index.json` 是搜索索引缓存文件（TTL 60 秒），属内部文件；前端列表与 `/api/raw/` 已过滤点前缀文件，属正常现象。
- 下载响应带 `CDN-Cache-Control: no-store`，**不进边缘缓存**，避免大文件占满缓存；预览（图片 / 视频）才走 `public, max-age=86400`。

## 14 · 安全注意事项

> 上线前逐条核对，别跳过

- **必须设置 `PASSWORD`**：006 没有默认密码。未设置时管理接口一律拒绝（`/api/verify` 返回 503），这本身就是保护。
- **必须设置 `AUTH_TOKEN`**：副 Worker 的令牌用于主副间鉴权，务必设置为长随机串，并开启 **Encrypt** 存储。006 在缺失时是一律拒绝而不是放行。
- **按需设置 `PUBLIC_READ`**：默认 `true` 是「分享门户」语义——任何人能列目录、能拿下载令牌。若不希望公开，设为 `false`，未登录访问列表 / 下载直接 401。
- **隐藏 `.` 开头的文件**：代码已禁止列表显示和下载点前缀文件（防 `.r2index.json` 泄露），不要解除该限制。
- **下载令牌**：非管理员访问 `/api/raw/` 需要 10 分钟内有效的 HMAC 令牌，且同 IP 每分钟限 20 次，防止盗链和批量抓取。
- **Turnstile**：强烈建议开启，且 **Site / Secret 必须成对配置**。
- **密码只存在服务端**：前端不再把明文密码写进 localStorage，只保存 12 小时的会话令牌；旧版本残留的 `r2_admin_pwd` 会在页面启动时被清除。
- **文件预览已消毒**：HTML / Markdown / Office 文件预览会先移除 `script`、`iframe`、`svg`、`on*`、`javascript:` 等内容再渲染，降低存储型 XSS 风险（自研黑名单，非白名单，仍建议不要上传来源不明的 HTML）。
- **密钥类环境变量加密**：`AUTH_TOKEN`、`TURNSTILE_SECRET_KEY`、`PASSWORD` 在控制台保存时选择 **Encrypt** 加密。
- **定期审计日志**：查看 Worker Logs（Settings → Logs）与 D1 操作日志，留意异常访问。

> ⛔ 本项目是「开源部署文档」性质的搭建文档，并非官方托管服务。
> 所有数据都存储在你自己的 Cloudflare 账号资源中；请保管好账号与各类密钥。
