# Cloudflare R2 跨账号聚合网盘 – 部署文档

本方案由**两个 Cloudflare Worker** 组成，实现 **多 R2 桶统一管理**（支持本地绑定 + 远程代理）、**大文件分块上传**、**操作日志（D1）**、**文件预览**、**搜索索引缓存**、**下载令牌防盗链**等功能。

---

## 1. 整体架构

- **主 Worker（`003_主_cloudflare D1数据库.js`）**：前端界面、聚合 API、D1 日志、Turnstile 人机验证。
- **副 Worker（`001副worker .js`）**：作为“远程 R2 代理”，封装单个 R2 桶的 API（也支持直接绑定在主 Worker 中，但副 Worker 用于跨账号/跨 Worker 的远程访问）。

部署后访问主 Worker 的域名即可使用网盘。

---

## 2. 准备工作

- 一个 **Cloudflare 账号**，开启 Workers 和 R2。
- 需要 **至少一个 R2 存储桶**（如 `my-bucket`）。
- （可选）**D1 数据库**用于记录操作日志 – 建议开启。
- （可选）**Turnstile** 用于管理员登录的人机验证。

---

## 3. 部署副 Worker（R2 代理）

### 3.1 创建 Worker
1. 在 Cloudflare Dashboard → Workers & Pages → 创建 Worker，命名为 `r2-proxy`（可自定义）。
2. 将 `001副worker .js` 的代码粘贴到编辑器中。

### 3.2 绑定 R2 存储桶
- 在 Worker 设置的 **“变量” → “R2 存储桶绑定”** 中，添加绑定：
  - **变量名称**：`MY_BUCKET`
  - **存储桶**：选择你的 R2 桶（如 `my-bucket`）。

### 3.3 环境变量（可选）
- `AUTH_TOKEN`：若设置，所有请求必须携带 `X-Auth-Token` 头与该值一致，否则返回 401。**若留空，则不鉴权**（仅建议内部使用）。

### 3.4 CORS 配置（重要）
副 Worker 代码中 `Access-Control-Allow-Origin` 硬编码为 `https://pan2.ppig.eu.cc`。  
**请根据你最终前端访问的实际域名修改**，或改为 `*` 以允许所有来源（不推荐生产）。  
搜索代码中的 `https://pan2.ppig.eu.cc`，替换为你的主 Worker 域名（例如 `https://your-domain.com`）。

```
[
  {
    "AllowedOrigins": [
      "https://pan2.ppig.eu.cc"
    ],
    "AllowedMethods": [
      "GET",
      "PUT",
      "POST",
      "DELETE",
      "HEAD"
    ],
    "AllowedHeaders": [
      "https://pan2.ppig.eu.cc"
    ],
    "ExposeHeaders": [],
    "MaxAgeSeconds": 3600
  }
]
```



### 3.5 部署并记下 Worker 域名
部署后，记录副 Worker 的 URL（如 `https://r2-proxy.your-username.workers.dev`），后续在主 Worker 的 `BUCKETS` 配置中使用。

## 4. 部署主 Worker（聚合与前端）

### 4.1 创建 Worker
1. 创建新 Worker，命名为 `r2-pan`（自定义）。
2. 将 `003_主_cloudflare D1数据库.js` 代码粘贴。

### 4.2 绑定资源
在 Worker 设置的 **“变量” → “R2 存储桶绑定”** 中，**绑定所有你需要直接管理的 R2 桶**（每个绑定一个变量名，如 `MY_BUCKET`, `BUCKET2`, `BUCKET3` 等）。

**注意**：绑定的变量名要与后面 `BUCKETS` JSON 配置中的 `binding` 字段一致。

### 4.3 绑定 D1 数据库（可选）
在 **“D1 数据库绑定”** 中：
- **变量名称**：`D1_DB`
- **数据库**：选择你创建的 D1 数据库（若未创建，请先在 D1 控制台创建并绑定）。

### 4.4 配置环境变量（必须）
在 Worker 的 **“变量” → “环境变量”** 中添加以下键值：

| 变量名                 | 说明                                                     | 示例                         |
| ---------------------- | -------------------------------------------------------- | ---------------------------- |
| `ADMIN`                | 管理员后台路径（不含 `/`）                               | `admin`                      |
| `PASSWORD`             | 管理员密码（至少 8 位）                                  | `yourStrongPassword`         |
| `BUCKETS`              | **JSON 数组**，定义所有可访问的桶（本地绑定 + 远程代理） | 见下方说明                   |
| `BG_URL`               | 背景图片 URL（用于代理防盗链）                           | `https://example.com/bg.jpg` |
| `TURNSTILE_SITE_KEY`   | Turnstile 站点密钥（可选）                               | `0x4...`                     |
| `TURNSTILE_SECRET_KEY` | Turnstile 密钥（可选）                                   | `0x4...`                     |

#### `BUCKETS` 格式说明
- **本地 R2 桶**：使用 `binding` 字段，对应绑定的变量名。
- **远程代理桶**：使用 `endpoint` 和 `token` 字段，指向副 Worker 的 URL 和 `AUTH_TOKEN`（若无则省略 token）。

**示例**（包含本地和远程）：
```json
[
  { "binding": "MY_BUCKET", "name": "主存储" },
  { "binding": "BUCKET2", "name": "备份存储" },
  { "endpoint": "https://r2-proxy.your-username.workers.dev", "token": "your-auth-token", "name": "远程副账号" }
]
```
- `name` 显示在前端桶下拉菜单中。
- 本地桶使用 `binding`，远程桶使用 `endpoint`。

### 4.5 修改 CORS 域名（与副 Worker 类似）
主 Worker 的 `Access-Control-Allow-Origin` 也硬编码为 `https://pan2.ppig.eu.cc`。  
**请改为你最终前端访问的域名**（即主 Worker 绑定的自定义域或 workers.dev 域名）。  
搜索代码中的 `https://pan2.ppig.eu.cc` 并替换。

### 4.6 部署主 Worker
保存并部署。部署后，访问主 Worker 的 URL（如 `https://r2-pan.your-username.workers.dev`）会看到登录界面。

## 5. 初始化与首次使用

### 5.1 管理员登录
- 访问主 Worker 域名 → 若未登录，显示管理员验证框。
- 输入你在 `PASSWORD` 中设置的密码。
- 若配置了 Turnstile，则需通过人机验证。
- 登录后进入文件管理界面。

### 5.2 初始化 D1 数据库（如已绑定）
- 登录后，切换到 **“操作日志”** 标签（如果出现“D1 日志”绿色标签则说明已配置）。
- 点击 **“初始化数据库”** 按钮，自动创建 `operation_logs` 表及索引。
- 或者直接访问 `/api/init-db-redirect` 并传入管理员密码（通过 `X-Admin-Password` 头）也会触发初始化并重定向到日志页。

### 5.3 设置存储桶
- 登录后，点击顶部下拉菜单 **“选择操作桶”**，选择你要上传/新建目录的目标桶。
- 文件列表会显示所有桶中当前前缀下的文件和文件夹（远程桶会通过 API 获取）。

## 6. 功能使用说明

### 6.1 文件管理
- **浏览**：点击文件夹进入子目录，面包屑导航可快速跳转。
- **搜索**：右上角输入关键词，会搜索所有桶中的文件和文件夹（基于索引缓存，60秒刷新）。
- **上传**：
  - 点击 **“上传文件”** 选择单个或多个文件；**“上传文件夹”** 保持目录结构。
  - 开启 **“时间戳”** 开关，文件会自动添加当日秒数（`_12345`）避免重名。
  - 支持大文件（>95MB）自动走**分块上传**，前端分块后合并。
- **移动**：选中文件/文件夹后点击 **“批量移动”**，在弹出的文件夹树中选择目标路径和桶。
- **删除**：支持单个删除或批量删除（选中后点击 “批量删除”）。
- **新建目录**：在当前路径下创建子文件夹。

### 6.2 文件操作（点击文件行）
- **预览**：支持常见图片（jpg/png/webp等）、PDF、Office文档（docx/xlsx/pptx等）、txt、md、csv。Office文档通过 Office Online 或本地转换库预览。
- **下载**：直接下载文件，链接附带 10 分钟有效令牌（防滥用）。
- **复制链接**：复制带令牌的分享链接，有效期 10 分钟（若未登录管理员，则必须携带令牌才能下载）。

### 6.3 操作日志（管理员）
- 所有文件操作（上传、下载、预览、删除、移动、新建目录）都会记录到 D1 数据库。
- 日志页面支持按操作类型筛选、按文件名搜索，分页查看。
- 记录包含时间、IP、操作、文件名、桶名和详情。

## 7. 安全与性能优化

- **下载令牌**：无论是否登录，下载都需携带有效令牌（管理员免检，但生成令牌仍基于密码）。
- **索引缓存**：每个桶的 `.r2index.json` 文件缓存 60 秒，减少 `list` 操作次数。
- **隐藏文件保护**：以 `.` 开头的文件和 `.r2index.json` 无法被下载或列出（管理员也看不到）。
- **CORS**：仅允许配置的域名访问，建议在生产环境中使用自定义域并绑定 SSL。

## 8. 自定义与扩展

### 8.1 更换背景
- 修改 `BG_URL` 环境变量为任意图片 URL（主 Worker 会代理该图片，解决防盗链问题）。
- 若代理失败，会降级为纯色渐变。

### 8.2 添加更多存储桶
- 本地：在 Worker 绑定新的 R2 桶，并在 `BUCKETS` 数组中添加对应项。
- 远程：部署更多副 Worker，并记录其 URL 和 token，添加到 `BUCKETS` 中。

### 8.3 修改上传分块大小
- 在 `CHUNK_SIZE` 变量（位于前端 JS 中）调整，单位字节，默认 `95 * 1024 * 1024`（95MB）。

## 9. 常见问题

**Q：为什么访问时显示“无效或过期的下载令牌”？**  
A：刷新页面，重新生成令牌（页面加载时会自动请求 `/api/download-token`）。

**Q：上传超大文件失败？**  
A：检查 Worker 的 CPU 时间和内存限制，分块上传可减轻压力。如果依然失败，可调小 `CHUNK_SIZE`。

**Q：远程桶无法访问？**  
A：确认副 Worker 已部署且 CORS 域名正确，token 与副 Worker 的 `AUTH_TOKEN` 一致。

**Q：D1 日志不记录？**  
A：检查 `D1_DB` 绑定是否正确，且已执行初始化。日志记录失败不会影响主业务，控制台会有错误输出。

**Q：如何重置管理员密码？**  
A：修改 `PASSWORD` 环境变量并重新部署 Worker 即可。

## 11. 关于文件冲突与时间戳

开启“时间戳”后，上传文件会自动在文件名末尾添加当天从 00:00 开始计算的秒数（五位数）。  
例如 `cat.jpg` → `cat_12345.jpg`，同一文件在同一天多次上传不会覆盖。
