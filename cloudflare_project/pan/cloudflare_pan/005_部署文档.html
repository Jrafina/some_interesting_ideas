01

项目架构

一个前端 Worker + 一个纯 API Worker，通过 R2 / D1 / Turnstile 组合工作
🖥️浏览器（用户）

直接访问主 Worker 渲染出的网盘前端页面与管理后台，无需单独托管前端。

▼HTTPS
🚀主 Worker（005_主worker.js）
渲染前端页面（/ 与 /admin） 管理员登录（密码 + Turnstile） 列表 / 搜索 / 上传 / 分块上传 新建目录 / 删除 / 移动 下载防盗链令牌（HMAC · 10 分钟） 背景图代理（/api/bg-image 带缓存） D1 操作日志（/api/logs） 多桶容量聚合（每桶 10GB 上限显示）
▼本地 R2 绑定直连　服务端代理转发（endpoint + token）
🗄️本地 R2 桶
绑定名 MY_BUCKET 及其扩展桶主 Worker 直接读写
🔧副 Worker（副worker.js）
纯 API：/api/list、/api/raw/、/api/upload 分块上传：initiate / upload-part / complete / abort 新建目录 / 删除 / 移动 / 容量统计 以 X-Auth-Token 鉴权 自带 R2 绑定 MY_BUCKET
▼副 Worker 自有 R2 绑定
🗄️远程 R2 桶（第二账号扩容）

副 Worker 放在另一个 Cloudflare 账号，即可把第二个账号的 R2 免费额度聚合进同一个网盘。

  • 主 Worker：一个文件内同时包含后端 API 与前端 HTML，负责页面渲染、登录鉴权、所有文件操作，并决定数据落在本地桶还是远程副桶。
  • 副 Worker：纯后端 R2 代理，不渲染页面。主 Worker 以「完整 URL + AUTH_TOKEN」方式服务端调用它，主要用途是跨账号 / 跨桶扩容。
  • D1 数据库：记录「下载 / 预览 / 上传 / 删除 / 新建目录 / 移动」等操作日志，供管理后台查询；未绑定 D1 时代码自动跳过，不影响主功能。
  • R2 搜索索引缓存：桶内自动维护 .r2index.json（TTL 60 秒），减少频繁全量扫描带来的 Class A 操作费用。

03

创建 R2 存储桶

Cloudflare 对象存储，本项目用它存放网盘文件

R2 免费额度约为 10GB 存储 / 每月 100 万次 Class A 操作 / 1000 万次 Class B 操作（以官网最新定价页为准）。 本项目内置的容量统计以每桶 10GB 为上限显示。

▸3.1 创建主桶

  1. 进入 R2 页面

    打开 dash.cloudflare.com → 左侧菜单 R2 → Create bucket。

  2. 填写桶信息

    输入桶名（例如 pan-storage），地区选择默认「自动」即可 → 点击 Create bucket。

  3. 记录桶名

    记下这个桶名，后面绑定 Worker 时需要选择它（主 Worker 的 MY_BUCKET 绑定指向它）。

▸3.2 创建副桶（可选）

  • 要用「副 Worker + 第二个账号的 R2」扩展容量时，用另一个 Cloudflare 账号（或同账号）再建一个桶，例如 pan-storage-2。
  • 只用主 Worker 单桶的话，跳过此步即可。
✅ 一个账号可以创建多个 R2 桶（主 Worker 支持挂多个本地桶，通过 MY_BUCKET2、MY_BUCKET3… 绑定并在 BUCKETS 中声明）。
04

创建 D1 数据库

Cloudflare 的无服务器 SQLite，用于记录网盘操作日志
  1. 进入 D1 页面

    左侧菜单 Workers & Pages → 顶部标签 D1 → Create database。

  2. 命名并创建

    输入数据库名（例如 pan-logs）→ 点击 Create。

  3. 记录数据库名

    后面绑定到主 Worker，变量名固定为 D1_DB。

⚠️ D1 不是必须的：未绑定时代码会静默跳过日志记录，网盘主功能不受影响， 但管理后台的「操作日志」面板不可用。表结构在部署后用 第 9 节 的按钮初始化。
05

创建 Turnstile 人机验证（可选，推荐）

Cloudflare 免费的无感验证码，防止管理密码被暴力破解
  1. 添加站点

    打开 dash.cloudflare.com → 左侧 Turnstile → Add site。

  2. 填写站点信息

    站点域名填你的主域名（如 ppig.eu.cc 或 pan2.ppig.eu.cc），Widget 模式选 Managed 或 Non-interactive。

  3. 记录 Site Key 与 Secret Key

    创建后会得到两个值：Site Key（挂到前端页面）、Secret Key（后端验证用），稍后填入主 Worker 环境变量 TURNSTILE_SITE_KEY / TURNSTILE_SECRET_KEY。

💡 不配置 Turnstile 时，登录只校验密码，功能不受影响；但强烈建议开启以防爆破。
06

部署副 Worker

副worker.js：纯后端 R2 代理 API，供主 Worker 跨账号聚合调用

▸6.1 创建 Worker 并粘贴代码

  1. 创建 Worker

    左侧菜单 Workers & Pages → Create application → Create Worker。

  2. 命名并部署

    输入名称，例如 pan-api（名称决定默认域名 pan-api.<你的子域>.workers.dev）→ 点击 Deploy。

  3. 粘贴代码

    创建完成后点击 Edit code，把 副worker.js 的全部内容粘贴进编辑器（替换默认模板）→ 点击右上角 Deploy。

▸6.2 绑定 R2 桶

  1. Worker 页面 → Settings → Variables and Secrets。
  2. 在 Bindings 区域 → R2 bucket bindings → Add binding。
  3. Variable name 填：MY_BUCKET（代码中固定使用，不要改）。
  4. Bucket 选择 3.2 节创建的副桶（如 pan-storage-2）→ Save。

▸6.3 设置认证令牌

  1. 仍在 Variables and Secrets 页面 → Environment Variables → Add。
  2. Variable name：AUTH_TOKEN。
  3. Value：生成一段长随机字符串（本地执行 openssl rand -hex 32，或用在线随机生成器），保存好，主 Worker 配置 BUCKETS 时要用。
  4. 建议点开 Encrypt 加密存储（保存前选择加密选项）。

▸6.4 自定义域名（可选）

  • 副 Worker 被主 Worker 用 https://…workers.dev 地址服务端调用，不需要自定义域名即可工作。
  • 若想给它独立域名：Worker → Settings → Domains & Routes → Add → 选 Custom Domain 或 Route。
🛑 CORS 提醒：副worker.js 第 64 行、第 73 行写死了 Access-Control-Allow-Origin: https://pan2.ppig.eu.cc。 如果你把副 Worker 的 API 直接暴露给浏览器使用（而非仅主 Worker 服务端代理），请按 第 8 节 改成你的主前端域名。
07

部署主 Worker

005_主worker.js：前端页面 + 管理后台 + 所有业务逻辑

▸7.1 创建 Worker 并粘贴代码

  1. Workers & Pages → Create application → Create Worker。
  2. 输入名称，例如 pan-web → 点击 Deploy。
  3. Edit code → 把 005_主worker.js 的全部内容粘贴进去（替换默认模板）→ 点击 Deploy。
  4. 此时可以先通过 https://pan-web.<你的子域>.workers.dev 访问测试（见 第 10 节），再继续配置。

▸7.2 绑定资源

路径：Settings → Variables and Secrets → Bindings，每个绑定单独添加一行：

类型变量名选择必填
R2 BucketMY_BUCKET3.1 节创建的主桶必填（代码默认引用）
D1 DatabaseD1_DB第 4 节创建的数据库可选（没有则无操作日志）
💡 若要在同一账号下挂更多本地 R2 桶，再添加 MY_BUCKET_2、MY_BUCKET_3 等绑定， 并在 BUCKETS 环境变量里按下面的格式声明。

▸7.3 设置环境变量

变量名说明默认值 / 示例
PASSWORD管理员密码默认 admin123，务必改成强密码
ADMIN管理后台路径默认 admin → 访问 /admin
BUCKETS聚合桶配置（JSON 字符串）见下方示例
BG_URL登录页背景图地址已内置默认壁纸 URL，可换成任意图片地址
TURNSTILE_SITE_KEYTurnstile Site Key（配合启用验证）可选
TURNSTILE_SECRET_KEYTurnstile Secret Key可选，建议加密存储

① 只用主 Worker 自己的桶（单桶最小配置）

BUCKETS
[{"binding":"MY_BUCKET","name":"主存储"}]

② 主桶 + 副 Worker 远程桶（两账号扩容）

BUCKETS
[{"binding":"MY_BUCKET","name":"主存储"},{"endpoint":"https://pan-api.<你的子域>.workers.dev","token":"<副worker的AUTH_TOKEN>","name":"副存储"}]

说明：endpoint 是副 Worker 的完整线上地址，token 必须与 6.3 节设置的 AUTH_TOKEN 完全一致。

③ 多个本地 R2 桶

BUCKETS
[{"binding":"MY_BUCKET","name":"主存储"},{"binding":"MY_BUCKET2","name":"备份存储"}]
✅ 若完全不设置 BUCKETS，代码默认按 [{"binding":"MY_BUCKET","name":"主存储"}] 工作，即只需要 MY_BUCKET 这一个 R2 绑定。

▸7.4 绑定自定义域名（关键步骤）

主 Worker 的前端页面由它自己渲染，建议把它挂到你的主域名上（如 pan2.ppig.eu.cc）：

  1. Worker 页面 → Settings → Domains & Routes → Add。
  2. 选 Custom Domain → 输入 pan2.ppig.eu.cc → 按提示在 DNS 处确认（域名已托管在 Cloudflare 时一键完成，自动添加 CNAME）。
  3. 等待证书生效（通常几秒到几分钟）。
🛑 CORS 提醒：005_主worker.js 第 160 行、第 169 行的 Access-Control-Allow-Origin 写死了 https://pan2.ppig.eu.cc。 若你的主域名不是它，请按 第 8 节修改后再部署，否则管理后台接口会因跨域被浏览器拦截。
08

修改 CORS 来源

仅当你的域名不是 pan2.ppig.eu.cc 时需要执行

在两个源文件中，把 https://pan2.ppig.eu.cc 全部替换为你自己的域名（例如 https://pan.example.com）：

文件需要修改的位置
005_主worker.js第 160 行（OPTIONS 响应头）、第 169 行（corsHeaders）
副worker.js第 64 行（OPTIONS 响应头）、第 73 行（corsHeaders）
  1. 修改代码

    用任意编辑器打开两个文件，将上述行中的域名替换成你的实际域名（两端须带 https://）。

  2. 重新部署

    回到对应 Worker 的 Edit code，重新粘贴修改后的代码并点击 Deploy。

  3. 确认访问方式

    若无自定义域名、仅用 *.workers.dev 测试，CORS 来源应改为你的 https://<名称>.<子域>.workers.dev 地址。

💡 顺带搜索一下两个文件中是否还有其他 pan2.ppig.eu.cc 字样（可全选复制后搜索），一次替换干净， 避免出现「页面打开但接口全挂」的 CORS 报错。
09

部署后初始化

只需执行一次的初始化步骤

▸9.1 初始化 D1 数据库

  1. 浏览器打开 https://<你的主域名>/admin（或你在 ADMIN 配置的路径）。
  2. 输入管理员密码登录（配置了 Turnstile 会先出人机验证）。
  3. 进入「操作日志」面板，点击页面上的 初始化 D1 数据库 按钮。
  4. 提示成功后会自动创建 operation_logs 表及 3 个索引，日志功能即可使用。

接口方式：POST /api/init-db（需带 X-Admin-Password 请求头）。

▸9.2 验证副 Worker 连通性（若配置了远程桶）

主 Worker 管理后台的「存储容量」面板应显示每个桶的已用容量、文件数和 10GB 上限； 若副桶显示错误信息，通常是 endpoint 或 token 写错了。

▸分块上传接口参数（主 Worker）

步骤请求方式携带参数
1. 初始化POST /api/multipart/initiateJSON：{key, bucket}
2. 上传分块PUT /api/multipart/upload-part请求头：X-Upload-Id、X-Part-Number、X-Target-Bucket；URL 参数：key；body：分块数据
3. 完成POST /api/multipart/completeJSON：{key, uploadId, parts, bucket}（parts 为分块 etag 列表）
4. 取消POST /api/multipart/abortJSON：{key, uploadId, bucket}

远程桶场景下，主 Worker 会自动追加 X-Auth-Token（副 Worker 令牌）转发给副 Worker；所有写操作统一携带 X-Admin-Password 请求头。

常见问题排查

▸其他说明

  • Worker 免费计划有 CPU 时长与每日请求限制；大流量场景请在 Workers 计划页面升级付费计划。

安全注意事项

上线前逐条核对，别跳过
  • 修改默认密码：PASSWORD 默认是 admin123，上线前必须更换为强随机密码。
  • 设置 AUTH_TOKEN：副 Worker 的令牌用于主副间鉴权，务必设置为长随机串，并开启 Encrypt 存储。
  • 隐藏 . 开头的文件：代码已禁止列表显示和下载点前缀文件（防 .r2index.json 泄露），不要解除该限制。
  • 下载令牌：非管理员访问 /api/raw/ 需要 10 分钟内有效的 HMAC 令牌，防止盗链和 Referer 伪造。
  • Turnstile：强烈建议开启，防止管理密码被暴力破解。
  • 密钥类环境变量加密：AUTH_TOKEN、TURNSTILE_SECRET_KEY、PASSWORD 在控制台保存时选择 Encrypt 加密。
  • 定期审计日志：查看 Worker Logs（Settings → Logs）与 D1 操作日志，留意异常访问。
