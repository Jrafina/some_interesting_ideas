# 📦 002_主_D1数据库.js 部署指示

## 新功能概述

相比原版 `001主worker_有预览.js`，新版本增加了：

| 功能 | 说明 |
|------|------|
| **D1 操作日志** | 记录每次下载、预览、上传、删除、新建目录、移动操作 |
| **日志查看器** | 管理员面板新增「📋 操作日志」标签，支持筛选和分页 |
| **背景图防盗链修复** | 通过 Worker 代理 `/api/bg-image` 获取背景图，绕过 haowallpaper.com 的 403 |

---

## 一、创建 D1 数据库

### 步骤 1：进入 Cloudflare Dashboard

1. 打开 [Cloudflare Dashboard](https://dash.cloudflare.com/)
2. 左侧菜单 → **Workers & Pages** → **D1**
3. 点击 **Create database**

### 步骤 2：创建数据库

```
数据库名称：cloudflare-pan-logs
位置：选择离你最近的区域（如 Asia Pacific）
```

点击 **Create**。

### 步骤 3：创建表结构

进入刚创建的数据库 → **Console**，粘贴执行以下 SQL：

```sql
CREATE TABLE IF NOT EXISTS operation_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  time TEXT NOT NULL,
  ip TEXT NOT NULL,
  operation TEXT NOT NULL,
  filename TEXT DEFAULT '',
  bucket TEXT DEFAULT '',
  details TEXT DEFAULT ''
);

CREATE INDEX IF NOT EXISTS idx_operation ON operation_logs(operation);
CREATE INDEX IF NOT EXISTS idx_time ON operation_logs(time);
CREATE INDEX IF NOT EXISTS idx_filename ON operation_logs(filename);
```

> 💡 也可以跳过这步，部署后在管理面板中点击「初始化数据库」按钮自动创建。

---

## 二、绑定 D1 到 Worker

### 步骤 1：进入 Worker 设置

1. **Workers & Pages** → 选择你的主 Worker
2. 点击 **Settings** → **Variables**

### 步骤 2：添加 D1 绑定

在 **D1 Database Bindings** 区域：

| 变量名 | D1 数据库 |
|--------|----------|
| `D1_DB` | `cloudflare-pan-logs` |

点击 **Add binding** → **Save and deploy**。

---

## 三、部署新 Worker 代码

### 方法 A：在线编辑器（推荐）

1. 进入 Worker → 点击 **Edit code**
2. 全选删除旧代码
3. 将 `002_主_D1数据库.js` 的全部内容粘贴进去
4. 点击 **Save and Deploy**

### 方法 B：Wrangler CLI

```bash
npx wrangler deploy 002_主_D1数据库.js
```

> 确保 `wrangler.toml` 中已配置好 D1 绑定和服务名称。

## 五、访问和使用

### 日志查看

1. 访问管理页面（如 `https://pan2.ppig.eu.cc/admin`）
2. 输入管理员密码解锁
3. 点击顶部 **📋 操作日志** 标签
4. 查看所有文件操作记录

### 日志筛选

- **操作类型**：下拉选择「下载/预览/上传/删除/新建目录/移动」
- **文件名搜索**：输入关键字后回车
- **分页**：每页 50 条记录，支持翻页

### 数据库初始化

如果日志页面显示为空且确认 D1 已绑定：
1. 在日志标签页点击 **「初始化数据库」** 按钮
2. 系统会自动创建 `operation_logs` 表和索引

## 六、防盗链修复说明

### 问题原因

`haowallpaper.com` 检测到 HTTP `Referer` 头部来自 `pan2.ppig.eu.cc`，触发了防盗链返回 403。

### 修复方案（双保险）

1. **Worker 代理端点** `/api/bg-image`：
   - Worker 以服务端身份请求原图（无 Referer）
   - 结果通过 Cache API 缓存 1 小时
   - 失败时降级为紫色渐变 SVG

2. **HTML `<meta>` 标签**：
   ```html
   <meta name="referrer" content="no-referrer">
   ```
   浏览器不会发送 Referer 头部

3. **CSS `background-image`**：
   ```css
   background-image: url('/api/bg-image');
   ```
   使用本地代理路径替代远程 URL

## 七、数据字段说明

`operation_logs` 表结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER | 自增主键（序号） |
| `time` | TEXT | ISO 8601 时间戳 |
| `ip` | TEXT | 操作者 IP（`CF-Connecting-IP`） |
| `operation` | TEXT | 操作类型：「下载」「预览」「上传」「上传(分块)」「删除」「新建目录」「移动」 |
| `filename` | TEXT | 操作的文件/目录名 |
| `bucket` | TEXT | 所在存储桶名称 |
| `details` | TEXT | 额外信息（文件大小、分块数、路径等） |

---

## 八、注意事项

1. **D1 是可选的**：如果未绑定 `D1_DB`，Worker 仍正常运作，只是不会记录日志。前端会显示「无日志」标记。

2. **日志不影响性能**：`logOperation()` 是异步的且不 `await`（fire-and-forget），失败也不会中断主业务。

3. **D1 免费额度**：Cloudflare D1 免费版包含每月 500 万行读取 + 10 万行写入，足够个人网盘使用。

4. **副 Worker 无需修改**：`001副worker .js` 保持不变，D1 日志只在主 Worker 端记录。

5. **背景图缓存**：`/api/bg-image` 使用 Worker Cache API，每小时刷新一次。如需立即更新，修改 `BG_URL` 环境变量后重新部署。
