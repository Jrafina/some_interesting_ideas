# 部署与换机说明

面向的场景：**换电脑、或者过几个月忘了当时怎么弄的**。
快速上手看 [README](README.md)，这份只讲「怎么恢复」和「怎么排查」。

---

## 一、换电脑部署

整个目录拷过去，然后：

```bash
# 1. 装Python 3.7+（Windows 安装时勾选 Add Python to PATH）

# 2. 配��置
cp config.example.json config.json
#    编辑 config.json，填 domain 和 token（或 authCode）

# 3. 体检
python doctor.py

# 4. 拿到要填进 Typora 的命令
python install.py
```

**没有 `pip install` 这一步** —— 全用标准库，不需要装任何依赖。

把第 4 步打印的命令填进 Typora（`偏好设置 → 图像 → 上传服务 → Custom Command`），
再跑一次 `python typora_config.py` 确认 Typora 侧真的记住了。

### 换机时最容易踩的坑

**Python 解释器路径会变。** 不同机器 / 不同 Python 安装位置，`python.exe` 的绝对路径不同。
Typora 里填的命令是**写死绝对路径**的，换机后大概率失效。

所以别手抄、别硬编码旧路径，用 `python install.py` 重新生成，它读的是当前解释器。

## 二、文件清单

```
typora-imgbed-uploader/
├── upload.py                上传桥（核心，Typora 调它）← 运行时必需
├── config.json              你的配置（含凭据，gitignore 了）  ← 运行时必需
├── config.example.json      配置模板
├── install.py               部署入口：检查 + 打印命令 + 语法自检
├── doctor.py                一键体检
├── typora_config.py         只读查看 Typora 实际设置
├── _test_urlencode.py       测试：URL 编码边界
├── _test_args.py            测试：参数解析边界
├── _test_typora_config.py   测试：Typora 配置解析
├── _mock_server.py          开发用：本地假图床
├── README.md                完整文档
└── 部署说明.md              本文件
```

> 只有 `upload.py` 和 `config.json` 是运行时必需的。下划线开头的是开发/测试文件，
> 删掉不影响使用（但如果你要改`upload.py`，建议留着测试）。

## 三、机制（换机后最容易忘的部分）

1. **Typora 只读 stdout**。脚本 stdout 只能吐最终 URL（一行一个）。
   所有日志必须走 stderr，否则 Typora 会把日志当 URL 插进文档。
2. **Typora 会把图片路径追加到命令后面**，所以命令里不要自己加参数。
3. **命令里的路径必须带双引号**。本机用户名目录常有空格（如 `My Documents`），
   不加引号会被拆成两段，Typora 就没反应。
4. **上传服务与主题是独立设置**，改上传服务不会影响主题。
5. **中文 / 全角 / emoji 文件名必须百分号编码**，否则浏览器 404。
   本工具已处理，但如果你改`upload.py` 别把编码去掉了。

## 四、怎么判断现在还好不好使

```bash
python doctor.py                # 全链路体检（会真传 2 张测试图）
python doctor.py --no-upload    # 只看静态配置
python typora_config.py         # Typora 侧有没有真的记住
```

`doctor.py` 会依次检查：解释器、文件、config 合法性、域名占位符、站点可达、
认证、真上传、外链可下载、中文文件名是否正确编码。全绿就没事。

## 五、改配置时不想传真图床

`doctor.py` 和手动测试都会往真图床传测试图。想避免留垃圾，先起本地假图床：

```bash
# 终端 1
python _mock_server.py 8971

# 终端 2
cp config.json /tmp/real.json
python -c "import json,io; c=json.load(io.open('config.json',encoding='utf-8-sig')); c['domain']='http://127.0.0.1:8971'; io.open('config.json','w',encoding='utf-8',newline='').write(json.dumps(c,ensure_ascii=False,indent=2))"
python doctor.py
cp /tmp/real.json config.json    # 记得改回来
```

改完 `upload.py` 建议跑三组测试：

```bash
python _test_urlencode.py && python _test_args.py && python _test_typora_config.py
```

## 六、排错

见 [README 的排错速查表](README.md#排错速查)。

补充两个排查技巧：

**看 stderr 的两行日志**：`→ POST ...` 和 `← publicUrl: ...`。
`→ POST` 出现说明 Typora 调用成功了，问题一定在服务端响应那一侧。

**隔离变量**：某一类输入失败时（比如只有中文名失败），
用**同一张图复制成不同文件名**逐个测，一次就能把「文件名」这个变量单独隔离出来。
