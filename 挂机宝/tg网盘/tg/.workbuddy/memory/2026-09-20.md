## 新功能：/rename（只改名字，不动位置）

- 需求：给存储池加"重命名"。文件与目录都能改，位置不动，零传输（Telegram 侧消息本来就没法改）。

- journal：目录改名复用 **`mvd`**（`{path:旧全路径, new:新全路径}`，`replay()` 的 mvd 分支本来就按前缀改写，

  `tools/rebuild_index.py` 同步加了 `ren` 分支（**部署包里也有这个文件，必须一起更新**）。
- 自测断言：改名后索引/位置/journal 都对、`/get` 仍能取回（message_id 没丢）、目录改名回复旧→新路径、
  子目录路径跟着变、同层重名拒绝、带 `/` 拒绝、根目录拒绝、名称未变不写 journal、`-file`/`-dir`、
  别名 `/ren`；「重放 == 现库」断言仍是绿的（这是 `ren` 写对了的唯一保证）。

## 用户报障：「/ls 文件路径」报路径不存在 + 要视频缩略图（同日）

### 现象与根因

用户贴出 bot 回复 `路径不存在：/收件箱/给阿嬷的情书（1）.mp4` + `用 /ls 查看根目录。`。
- 这条文案**只有 `_reply_ls` 会发** → 用户跑的是 `/ls`，不是 `/get`；
- 库里文件好好的：`id=13 / 给阿嬷的情书（1）.mp4 / folder_id=1(收件箱) / video/mp4 / 1.27 GB`；
- **根因**：`_reply_ls` 走 `_resolve_path()`，它**只查 `folders` 表**——文件不在查找范围，
  所以路径再正确也报「路径不存在」。而 `/get`/`/rm`/`/move`/`/rename` 走的 `_resolve_node()`
  对同一路径返回 `('file', 13, None)`，完全正常。
- **已修**：`_reply_ls` 目录解析失败时再用 `_resolve_node()` 看一眼，是文件就回
  「「xxx」是文件，不是目录 —— /ls 只能列目录 / 取回它：/get <路径> / 看它所在的目录：/ls <父目录>」。

### 第二个问题：为什么 /收件箱 只出了一个 jpg 缩略图、没有 mp4 的

先做真机探针（`_probe_box.py`），**实测数据**：

| 文件 | file_id 底层类型 | sendPhoto | sendVideo | sendDocument |
|---|---|---|---|---|
| 给阿嬷的情书（1）.mp4 | **Video** | ✗ can't use file of type Video as Photo | ✓ | ✓ |
| 584_...jpg | **Document** | ✗ can't use file of type Document as Photo | ✓ | ✓ |

相册组合：`纯 video ✓`、`纯 document（相同型）✓`、`photo+video ✗`（因 jpg 是 document）、
`photo+document ✗`、`两个都当 document ✗ MEDIA_INVALID`（video 型项当 document 会炸）。
→ 旧逻辑 ①②③ 全挂，最后退到"只发图片(document)" 1 项 → 单发 `sendDocument` =
**用户看到的那一个 jpg**。诊断闭环。

## /ls 文字清单加行首序号（同日，用户要求）

- 需求：`/ls` 的文件行前面加 `1. 2. 3.`。用户给了目标样子，**行尾的 `· #13` 保留**。
- 实现：`for i, f_ in enumerate(files_, 1): lines.append(f"{i}. {f_['name']}   {_human(...)} · #{f_['id']}")`
  —— 去掉了原来的两空格缩进，与用户示例一致。**子目录行不加序号**（进目录用路径，编号没有意义）。
- ⚠️ **关键坑：序号 ≠ 编号**。`files_` 是 `ORDER BY id DESC`，序号 1 是最新的，但它的 `#id`
  可能是 13。以前底部提示写「取文件：/get 编号」，加了序号后这句就歧义了 ——
  **`/get 1` 会去取 id=1 的文件，不是列表第 1 行**。故把三处文案统一成「`/get #编号（行尾那个 #数字）」：
  `/ls` 底部、`HELP_TEXT`、`/get` 的用法报错。
- 自测 282 → **287 / 0**（新增：序号连续 1..N、序号与 `#id` 并存、子目录行无序号、底部提示文案）。
- 上线：备份 `app.py.bak-ls-number-20260920`，md5 `f8f75b06103f7257665fb58fd20b2179`，restart → active，
  服务器自测 287/0，`--verify` 通过。
- 真机验收（`/ls /收件箱`、`/ls /`，跑完自删消息）输出与用户示例**逐字符一致**，
